Power-of-two Hi-Z from a render-size depth buffer

Many renderers keep the Hi-Z pyramid at a power of two (niagara uses the previous power of two of the screen size), so every level after the first halves cleanly and a texel's UV maps to a whole number of texels at every level. The first level is then a resample: 1920 → 1024 is 1.875 source texels per Hi-Z texel, and a texel's area can touch three source texels per axis. With source.resample: 'area', Hi-Z texel x folds every depth texel that [x·W/n, (x+1)·W/n) overlaps, so min and max stay conservative at every level. A 2048 × 1024 pyramid takes 2 dispatches for 12 levels.

For comparison, the readout builds the pyramid niagara does: one 2×2 tap at each texel centre for the first level (what a min/max reduction sampler returns; WebGPU has none, so a small shader takes the four loads), then exact 2×2 levels. It misses depth texels wherever a texel's area spans three, which can cull visible objects. The readout counts those misses against every depth texel, and the right-hand view marks them: in red where the miss is larger than 0.01 in depth (object edges, where culling goes wrong), in orange where it is smaller (sloped surfaces). 

const hiZ = device.createTexture( { format: 'rg32float', size: [ 1024, 512 ], mipLevelCount: 11,
	usage: GPUTextureUsage.TEXTURE_BINDING | GPUTextureUsage.STORAGE_BINDING } );
downsampler.encode( encoder, hiZ, { source: { texture: depth, resample: 'area' }, reduction: 'minmax' } );  // r = min, g = max
