Odd sizes: 'exact', 'spd' and 'box'

A 2:1 reduction is exact only when a size halves cleanly. The same rgba8unorm image goes through the three oddSizes policies, next to the area-weighted ideal: each texel of level l is the exact mean of the base texels under its normalized area, [x·W/n, (x+1)·W/n) per axis (computed here on the CPU in f64, straight from level 0). The table gives each policy's error against it.

  • 'exact' (default) reproduces render-pass and WebGL mipmaps: bilinear at normalized coordinates. At 3 → 1 it takes only the centre texel, so a 31×31 image can reduce to an unrepresentative 1×1.
  • 'spd' is AMD SPD's: clamped loads with the last odd row or column dropped (watch the bright line on the last row and column disappear), and footprints that drift towards the far edge.
  • 'box' is nvpro_pyramid's area weighting: along an odd size 2n+1, taps 2x … 2x+2 with weights (n−x, n, x+1)/(2n+1). Every level keeps the base level's mean, so its 1×1 is the image's mean.
downsampler.encode( encoder, texture );                      // 'exact': render-pass mipmaps
downsampler.encode( encoder, texture, { oddSizes: 'spd' } ); // SPD: fewest dispatches, drops odd edges
downsampler.encode( encoder, texture, { oddSizes: 'box' } ); // area-weighted: GI, irradiance, roughness, UI
