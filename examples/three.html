three.js integration: downsampler/three

generateMipmaps( renderer, texture ) generates a three.js texture's mip chain with compute shaders. The texture must already be allocated on the GPU with storage usage, which in current three.js means a StorageTexture. It returns false and does nothing when it can't, so you can fall back to three's own path. Set mipmapsAutoUpdate = false so three doesn't regenerate them with render passes after a compute write.

Both planes show the same 1000 × 1000 image, repeated, receding into the distance. Left: three's own render-pass mipmaps (a DataTexture). Right: the same image in a StorageTexture, mipmapped by downsampler. The default odd-size policy matches render passes, so they should look the same. The readout checks our levels against the library's CPU reference and reports how far three's levels are from ours. 

import { generateMipmaps, requiredLimits } from 'downsampler/three';

const renderer = new THREE.WebGPURenderer( { requiredLimits: requiredLimits( await navigator.gpu.requestAdapter() ) } );
await renderer.init();
const texture = new THREE.StorageTexture( 1000, 1000 );
texture.generateMipmaps = true;           // allocate the full chain
texture.mipmapsAutoUpdate = false;        // we write the mips
texture.minFilter = THREE.LinearMipmapLinearFilter;
// … write level 0 (a compute pass, or writeTexture on its GPUTexture) …
if ( ! generateMipmaps( renderer, texture ) ) { /* not allocated or unsupported: use three's own path */ }
