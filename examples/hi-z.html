Hi-Z (min/max) pyramid from a depth buffer

A render pass draws a few dozen sloped rectangles into a 1280 × 720 depth32float buffer. Depth formats can't be storage textures, so the pyramid goes into a separate rg32float texture, with the depth buffer as a source: level 0 is a copy (same size), and every level after it holds (min, max) of the depth texels it covers. The chain is recorded with encodePass into a compute pass of the same encoder.

Odd sizes (720 → 360 → 180 → 90 → 45 → 22 …) include the extra row or column, so every texel bounds all the depth texels under it: the pyramid is conservative, which is what occlusion culling needs (an object is hidden if its nearest depth is behind the tile's max; with reverse-Z, compare with min). The readout checks this independently of the library, and shows what an SPD-style max pyramid (last odd row or column dropped) would miss. For a power-of-two pyramid from the same depth buffer (source.resample: 'area'), see hi-z-pow2.html. 

const hiZ = device.createTexture( { format: 'rg32float', size: [ 1280, 720 ], mipLevelCount: 11,
	usage: GPUTextureUsage.TEXTURE_BINDING | GPUTextureUsage.STORAGE_BINDING } );
const pass = encoder.beginComputePass();
downsampler.encodePass( pass, hiZ, { source: { texture: depth }, reduction: 'minmax' } );  // r = min, g = max
pass.end();
