Hi-Z (min/max) pyramid from a depth buffer

A render pass draws a few dozen sloped rectangles into a 1280 × 720 depth32float buffer. Depth formats can't be storage textures, so the pyramid goes into a separate rg32float texture, with the depth buffer as a source: level 0 is a copy (same size), and every level after it holds (min, max) of the depth texels it covers. The chain is recorded with encodePass into a compute pass of the same encoder.

Odd sizes (635 → 317 → 158 → 79 → 39 → 19 …) include the extra row or column, so every texel bounds all the depth texels under it: the pyramid is conservative, which is what occlusion culling needs (an object is hidden if its nearest depth is behind the tile's max; with reverse-Z, compare with min). The readout checks this independently of the library, and shows what an SPD-style max pyramid (last odd row or column dropped) would miss. For a power-of-two pyramid from the same depth buffer (source.resample: 'area'), see hi-z-pow2.html. 

const hiZ = device.createTexture( { format: 'rg32float', size: [ width, height ], mipLevelCount,
	usage: GPUTextureUsage.TEXTURE_BINDING | GPUTextureUsage.STORAGE_BINDING } );
const pass = encoder.beginComputePass();
downsampler.encodePass( pass, hiZ, { source: depth, reduction: 'minmax' } );  // r = min, g = max
pass.end();

Readout

    Candidate draws beside a thin occluder

    A fixed three-pixel strip and a broad rectangle are depth occluders in the upper half; seeded sloped rectangles fill the lower half. Candidate rectangles have a constant nearest depth. CPU code tests the GPU pyramid readback at mip 4, using every overlapped tile's maximum, and compares each decision with every covered full-resolution depth pixel. Green outlines are kept; gray outlines are culled. Keeping a hidden object is conservative extra work; culling a visible object is a failure. These are candidate draw decisions, not measured render draw calls.
